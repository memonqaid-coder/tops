Q:Explain why the program crashes on an empty string input and describe the check
  your pointer-based solution must perform before dereferencing the pointer. How does traversing
  a string using a pointer differ from traversing it using array index notation, and which approach
  makes the empty-input bug easier to catch?
A: >Why the Program Crashes on an Empty String Input
      When a user presses Enter without typing anything, the input buffer stores either:
        -An empty string consisting of just the null terminator ("\0"), or
        -A newline character followed by a null terminator ("\n\0"), depending on the input 
         function used (e.g., fgets vs. scanf).
      The crash (typically a Segmentation Fault or undefined behavior) usually occurs because:
        -Null Pointer Dereference:
             If reading input fails (e.g., fgets() returns NULL) and the pointer is initialized 
             to NULL or left dangling, attempting to dereference it (*ptr) will crash the 
             program.
        -Out-of-Bounds Memory Access: 
             If the code attempts to skip or trim leading whitespace/newlines assuming valid 
             characters exist, it may increment the pointer past the null terminator into 
             unallocated or restricted memory locations, leading to a memory access violation.
   >Check Required Before Dereferencing the Pointer:
      Before dereferencing the pointer or advancing through the string, your code must perform
      two essential checks:
        -Check for NULL Pointer: 
             Ensure the pointer itself actually points to a valid memory address.
        -Check for the Null Terminator ('\0'): 
             Ensure the pointer is not pointing to the end of the string before 
             attempting to read or process the character.

   >Which Approach Makes the Bug Easier to Catch?
      ->Array index notation (str[i]) generally makes this bug easier to catch and prevent 
        for beginners because:
       -Explicit Bounds Check: 
          The loop condition str[i] != '\0' explicitly checks index 0 right away. If 
          str[0] == '\0', the loop body immediately fails and never executes.
       -Preserves Base Reference: 
          You always know str[0] is the first character. With pointers, if you advance 
          ptr++ without checking *ptr != '\0', you lose track of the boundary immediately and 
          wander into invalid memory.
